part 2 Github workflow: 

Issues are a task, bug, or a feature request opened to the owners of the repo. 
A branch is a serpate version of the source code. 
A commit is a saved version of any changes you made that contains a message of what you changed. 
A PR is a request from you to merge code changes in to another branch that also allows the code owners to review your PR first before accepting and merging. 
The default branch is the branch that github uses by default.

## A short explanation of how the issue, branch, commits, review, and pull request relate to one another

1 the issue was created by a third party developer (myself). Then you checkout a new branch based off of main to work on the said issue. After making the changes I commit them one by one to have one huge commit with a bunch of changes. After I push all the commits to my feature branch I then open up a PR on github that's ready for review by an engineer(s) that owns the repo. It then get's approved with no more changes required and gets merged in by the owner engineer of the repo.
